# 02.6 - Esquemas Pydantic y Capa CRUD

> Enlace de navegación: Volver al [[02.0 - Indice y Mapa de El Motor Backend]]

## Análisis Técnico: Separación de Responsabilidades

El motor backend de QuestFest implementa el patrón de diseño de **Separación de Responsabilidades (SOC)** dividido en 3 capas de software desacopladas:

1. **Capa de Controladores (Routers en `app/api/routers/`)**: Intercepta las solicitudes [[06.1 - Que es una API RESTful y como funciona|HTTP REST]], aplica las dependencias de autenticación y estructura la respuesta de salida.
2. **Capa de Validación y DTOs (Esquemas Pydantic en `app/schemas/`)**: Evalúa y convalida que la información de entrada (payload JSON) cumple los tipos de datos requeridos antes de permitir la ejecución de la lógica de negocio.
3. **Capa de Acceso a Datos (Operaciones CRUD en `app/crud/`)**: Encapsula las consultas asíncronas SQL sobre PostgreSQL utilizando [[06.8 - Que es un ORM y como funciona SQLAlchemy|SQLAlchemy 2.0 ORM]] (`AsyncSession`).

---

## Esquemas Pydantic: Validación de DTOs (`app/schemas/`)

Pydantic opera como una barrera de convalidación de datos:
- **`user_schemas.py`**: Define objetos DTO como `UserCreate`, `UserResponse` y `TokenData`. Evita la exposición indebida de atributos confidenciales como el campo `password_hash` en las respuestas de la API.
- **`misiones_schemas.py`**: Estructura los objetos `SuggestMissionRequest`, `CompleteMissionRequest` (para la recepción de evidencias) y `MissionResponse`.
- **`apuestas_schemas.py`**: Valida las cuotas y estructuras [[06.10 - Tipos de Datos JSONB en PostgreSQL|JSONB]] enviadas al crear mercados (`SuggestBetRequest`) y colocar participaciones (`PlaceBetRequest`).
- **`duelos_schemas.py`**: Define los parámetros de creación (`DuelCreateRequest`) y la propuesta de resolución del vencedor (`ResolveDuelRequest`).

---

## Capa CRUD: Consultas Asíncronas SQL (`app/crud/`)

Las funciones contenidas en la carpeta `crud/` ejecutan la lógica transaccional pura:
- **`user_crud.py`**: Búsqueda de usuarios por identificador o nombre de usuario (`get_user_by_username`).
- **`misiones_crud.py`**: Gestiona el catálogo de misiones activas, el cómputo de votos comunitarios (`vote_mission`) y el registro de pruebas (`submit_mission_proof`).
- **`duelos_crud.py`**: Ejecuta la inmovilización de saldos de **QuestCoins** al aceptar o lanzar duelos y la liquidación final a favor del vencedor.
- **`ledger_crud.py`**: Registra de forma atómica cada modificación de saldo en la tabla de auditoría financiera.

## Modelo Conceptual de Analogía: Formulario de Ventanilla y Archivador Bancario

Para comprender la función de Pydantic y la capa CRUD, puede analizarse mediante la analogía de una ventanilla de atención bancaria:

1. **El Formulario de Convalidación (Esquemas Pydantic)**:
   Funciona como la solicitud en papel oficial exigida para realizar un trámite. Si la solicitud carece del tipo de datos adecuado o prescinde de un campo obligatorio, el empleado de la ventanilla rechaza el documento de forma inmediata (código de error 422 Unprocessable Entity) sin derivar la petición a los sistemas centrales.

2. **El Encargado de Custodia de la Caja Fuerte (Capa CRUD)**:
   Representa a los empleados autorizados para acceder a los archivadores de la caja fuerte. Ninguna pantalla del sistema manipula directamente la base de datos; la solicitud se traslada al encargado de la capa CRUD, el cual verifica el saldo de QuestCoins y ejecuta el asiento correspondiente.

---

## Decisiones de Arquitectura de Software

- **Desacoplamiento de Operaciones CRUD**: Aislar las consultas SQL de los controladores API permite reutilizar las operaciones de lectura y modificación desde múltiples puntos del backend (por ejemplo, ajustar el saldo de un usuario desde la consola de administración o desde la resolución de un duelo).
- **Procesamiento Asíncrono (`AsyncSession`)**: La ejecución mediante `await db.execute(...)` garantiza que el servidor de FastAPI no se bloquee durante la espera de las respuestas de PostgreSQL, manteniendo la disponibilidad para atender otras solicitudes concurrentes ([[06.2 - La Asincronia en Python y FastAPI|Asincronía en FastAPI]]).
