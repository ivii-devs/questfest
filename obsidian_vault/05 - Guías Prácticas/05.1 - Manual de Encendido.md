## Procedimiento Técnico de Puesta en Marcha

Este manual detalla los pasos operativos estandarizados para la compilación, despliegue y ejecución de los entornos de base de datos, backend API y cliente frontend del proyecto **QuestFest**.

### 1. Definición de Variables de Entorno (`.env`)

Se debe comprobar la existencia y validez de los archivos de entorno en los directorios correspondientes:

#### Archivo `backend/.env`:
```ini
POSTGRES_USER=questfest_user
POSTGRES_PASSWORD=tu_password_segura
POSTGRES_DB=questfest_db
DATABASE_URL=postgresql+asyncpg://questfest_user:tu_password_segura@db:5432/questfest_db
SECRET_KEY=clave_secreta_para_firmar_jwt_tokens
CLOUDINARY_CLOUD_NAME=tu_cloud_name
CLOUDINARY_API_KEY=tu_api_key
CLOUDINARY_API_SECRET=tu_api_secret
```

#### Archivo `frontend/.env.local`:
```ini
NEXT_PUBLIC_API_URL=http://localhost:8000
```

---

### 2. Despliegue de Servicios Backend con Docker

Desde la terminal, situarse en el directorio `backend/` e iniciar los servicios mediante [[06.15 - Contenedores y Virtualizacion con Docker|Docker Compose]]:

```bash
# Compilar y arrancar los contenedores de PostgreSQL y FastAPI en segundo plano
docker-compose up -d --build

# Verificar el estado operativo de los servicios
docker-compose ps

# Monitorizar la emisión de logs de la API en tiempo real
docker-compose logs -f web
```

---

### 3. Aplicación de Migraciones de Base de Datos con Alembic

Para inicializar la estructura relacional o aplicar cambios pendientes en los modelos, se ejecutan las migraciones de [[06.9 - Migraciones de Base de Datos con Alembic|Alembic]] dentro del contenedor de la aplicación:

```bash
# Aplicar todas las migraciones pendientes hacia la revisión más reciente
docker-compose exec web alembic upgrade head

# Generar un script de revisión automática tras modificar modelos ORM:
docker-compose exec web alembic revision --autogenerate -m "Descripcion de los cambios"
```

---

### 4. Ejecución de la Interfaz Cliente (Next.js)

En una nueva terminal, acceder al directorio `frontend/` y arrancar el servidor de desarrollo:

```bash
# Instalación de módulos de Node.js (solo en la primera ejecución)
npm install

# Iniciar el servidor de desarrollo en el puerto 3000
npm run dev
```

Puntos de acceso de la infraestructura:
- **Cliente Web**: `http://localhost:3000` (accesible en red local Wi-Fi vía `http://192.168.x.x:3000`).
- **Documentación Interactiva Swagger**: `http://localhost:8000/docs` ([[06.4 - Documentacion Automatica con Swagger y OpenAPI|OpenAPI UI]]).

## Modelo Funcional de Secuencia Operativa

La secuencia de despliegue se organiza en cuatro fases operativas:

1. **Configuración de Credenciales (`.env`)**: Establece las claves criptográficas para la firma de tokens JWT y la conexión con el almacenamiento CDN de Cloudinary.
2. **Activación de Infraestructura (`docker-compose up`)**: Levanta en contenedores aislados la base de datos PostgreSQL y el servidor FastAPI, garantizando la paridad del entorno.
3. **Inicialización Contable (`alembic upgrade head`)**: Modela el esquema relacional preparando las tablas de usuarios, QuestCoins, misiones y duelos.
4. **Despliegue de Interfaz (`npm run dev`)**: Inicia la aplicación React en el puerto 3000 para permitir el acceso de los dispositivos móviles a la red del evento.

## Diagnóstico y Solución de Incidencias (Troubleshooting)

- **Fallo de Conexión a Base de Datos en Contenedor**: 
  Si el contenedor de la API muestra errores de conexión con la base de datos, verificar que `DATABASE_URL` especifique el nombre del servicio interno `@db:5432` y no `@localhost:5432`.
- **Bloqueo por Política CORS en Dispositivos Móviles**: 
  Verificar que la IP asignada al dispositivo se encuentre dentro de los rangos autorizados por la expresión regular en `CORSMiddleware` ([[06.3 - Politicas CORS y Seguridad en Navegadores|Políticas CORS]]).
