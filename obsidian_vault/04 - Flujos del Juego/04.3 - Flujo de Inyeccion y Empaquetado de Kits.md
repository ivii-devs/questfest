## Explicación Técnica: Diagramas de Secuencia e Interacciones Transaccionales

El ciclo operativo de los Kits de Eventos comprende dos flujos principales: la **Inyección Atómica en una Comunidad** y el **Empaquetado de Retos desde un Grupo Activo**.

### 1. Flujo de Inyección Atómica en Comunidad

Este flujo describe la interacción entre el anfitrión, la interfaz PWA, el servicio de verificación de permisos y la base de datos PostgreSQL:

```mermaid
sequenceDiagram
    autonumber
    actor Admin as Anfitrión del Grupo
    participant UI as Interfaz PWA (KitPreviewAndInjectModal)
    participant API as Endpoint Backend (/api/v1/grupos/{id}/kits/inject)
    participant Auth as Guardián (verify_group_admin)
    participant DB as PostgreSQL (Transacción ACID)

    Admin->>UI: Pulsa "Usar en un grupo" y selecciona comunidad
    UI->>UI: Despliega acordeones de misiones, ruletas y apuestas
    Admin->>UI: Modifica textos y asigna participantes reales a las cuotas
    Admin->>UI: Pulsa "Inyectar en el Grupo"
    UI->>API: POST con payload de items seleccionados
    API->>Auth: Validar si el usuario tiene rol admin en grupo_id
    alt Permiso Denegado
        Auth-->>API: Error HTTP 403 Forbidden
        API-->>UI: Denegación de acceso territorial
        UI-->>Admin: Muestra notificación de error
    else Permiso Concedido
        Auth-->>API: Autorización verificada
        API->>DB: Iniciar db.begin()
        API->>DB: INSERT misiones regulares (es_ruleta=False)
        API->>DB: INSERT misiones de ruleta (es_ruleta=True)
        API->>DB: INSERT apuestas con cuotas indexadas
        API->>DB: UPDATE kits_eventos SET descargas_count = descargas_count + 1
        DB-->>API: Transacción confirmada (COMMIT)
        API-->>UI: HTTP 200 OK (InyeccionKitResponse)
        UI-->>Admin: Notificación de éxito y redirección al Feed
    end
```

### 2. Flujo de Empaquetado Inverso (Guardar como Kit)

Este flujo permite a un anfitrión transformar los retos activos de su grupo en un nuevo kit reutilizable:

```mermaid
sequenceDiagram
    autonumber
    actor Admin as Anfitrión del Grupo
    participant UI as Panel Admin (SaveGroupAsKitModal)
    participant API as Endpoint Backend (/api/v1/kits)
    participant DB as PostgreSQL

    Admin->>UI: Pulsa "Guardar como Kit" en ajustes de grupo
    UI->>API: GET misiones y apuestas activas del grupo
    API-->>UI: Listado de entidades existentes
    Admin->>UI: Marca casillas de retos deseados y define título/categoría
    Admin->>UI: Pulsa "Empaquetar y Guardar Kit"
    UI->>API: POST /api/v1/kits con ContenidoKitSchema consolidado
    API->>DB: INSERT kit_eventos con campo JSONB
    DB-->>API: Registro creado con ID único
    API-->>UI: HTTP 201 Created (KitResponse)
    UI-->>Admin: Confirmación de kit guardado en el catálogo
```

## Analogía en el Mundo Real

El flujo de inyección es comparable al de encargar un menú temático cerrado a una empresa de catering. El cliente abre el catálogo y elige el "Menú Degustación Barbacoa". En la comanda preliminar, el cliente especifica que quiere sustituir los entrantes picantes por ensaladas (edición inline) y anota los nombres de los comensales celíacos o vegetarianos (asistente de arquetipos). Cuando el catering confirma el pedido, la comida se prepara y se entrega en la fiesta del cliente. La cocina del catering no interfiere con el disfrute de la fiesta, ni la fiesta altera el menú original archivado en las oficinas centrales.

---

## Aplicación en QuestFest

- Garantiza que ninguna inyección deje misiones a medio crear si ocurre un fallo de red o un error imprevisto (atomicidad en PostgreSQL).
- Asegura que los administradores mantengan el control sobre el ritmo de su evento pudiendo elegir entre publicación inmediata o guardado como borradores.
- Valida matemáticamente que un participante sin rango de administrador no pueda inyectar contenido en comunidades ajenas.
