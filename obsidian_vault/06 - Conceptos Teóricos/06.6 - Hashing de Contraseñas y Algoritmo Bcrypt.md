# 06.6 - Hashing de Contraseñas y Algoritmo Bcrypt

> Enlace de navegación: Volver al [[06.0 - Indice y Mapa de Conceptos Teoricos]]

---

## Explicación Técnica

El **hashing de contraseñas** es la práctica criptográfica de transformar una cadena de texto en claro en una representación alfanumérica de longitud fija mediante una función matemática unidireccional.

1. **Irreversibilidad Matemática (Unidireccionalidad)**: Una función hash como **Bcrypt** permite calcular el hash a partir de la contraseña, pero es matemáticamente imposible revertir el resultado para obtener la contraseña original.
2. **Adición de Sal (Salting)**: Antes de calcular el hash, el algoritmo genera una cadena aleatoria única llamada _salt_ que se concatena a la contraseña. Esto impide que atacantes utilicen tablas preconmensuradas (_Rainbow Tables_) para adivinar contraseñas comunes.
3. **Factor de Coste Adaptable (Cost Factor)**: Bcrypt incluye un parámetro de lentitud intencionada. Esto hace que intentar adivinar una contraseña probando millones de combinaciones por segundo (_ataque de fuerza bruta_) sea impracticable debido al tiempo de cómputo requerido por cada intento.

---

## Analogía de la Trituradora Microcortante

Para comprender la diferencia entre cifrado reversible y hashing unidireccional, se puede analizar mediante la analogía del procesamiento de documentos:

- **Cifrado Tradicional (Reversible)**: Equivale a guardar un documento dentro de un cofre bajo llave. Poseer la llave permite abrir la cerradura y recuperar el documento original intacto.
- **Hashing Criptográfico con Bcrypt (Irreversible)**: Equivale a procesar el documento mediante una **trituradora microcortante de alta seguridad**.
  - La hoja queda reducida a una composición única de micropartículas inaccesibles. Resulta técnicamente imposible reconstruir el texto original a partir del residuo obtenido.
  - Para verificar la clave durante un inicio de sesión, el sistema procesa la contraseña introducida mediante la misma trituradora y **compara si el patrón de partículas resultante coincide de forma exacta con el registro depositado en la base de datos**.

---

## Aplicación en el Proyecto QuestFest

En **QuestFest**, el servidor de FastAPI utiliza la librería `passlib` configurada con el esquema `bcrypt`. Cuando un jugador se registra, la contraseña introducida en la pantalla pasa por la función `get_password_hash()`. Únicamente la cadena del hash resultante se almacena en el campo `password_hash` de la tabla `usuarios` en PostgreSQL. Ni los administradores de la base de datos ni nadie puede conocer la contraseña original del jugador.
