## Explicación Técnica

**Docker** es una plataforma de virtualización a nivel de sistema operativo que permite empaquetar una aplicación junto con sus dependencias, binarios y librerías en una unidad estandarizada llamada **contenedor**.

1. **Diferencia entre Contenedor y Máquina Virtual (VM)**:
   - **Máquinas Virtuales**: Incluyen un sistema operativo invitado completo (_Guest OS_) sobre un hipervisor, lo que consume gigabytes de RAM y recursos de CPU.
   - **Contenedores Docker**: Comparten el mismo núcleo (kernel) del sistema operativo anfitrión, siendo extremadamente ligeros, arrancando en milisegundos y consumiendo una fracción mínima de recursos.
2. **Imágenes Docker y Dockerfile**: Un `Dockerfile` es un script de instrucciones paso a paso para construir una imagen inmutable (ejemplo: instalar Python 3.11, copiar código y ejecutar `pip install`).
3. **Orquestación con Docker Compose (`docker-compose.yml`)**: Es una herramienta que permite definir y ejecutar aplicaciones compuestas por múltiples contenedores interconectados (ejemplo: un contenedor para FastAPI y otro contenedor aislado para PostgreSQL), gestionando sus redes internas y volúmenes de almacenamiento persistente.

## Analogía del Contenedor de Carga Estándar

Para comprender la función de Docker en el software, se puede analizar mediante la analogía de la logística de transporte intermodal:

- **Despliegue Tradicional (Heterogéneo)**: Equivale a transportar mercancías de diferentes formas y tamaños de manera suelta. Cada medio de transporte (servidor) exige una disposición específica y se corren riesgos de incompatibilidad entre piezas.
- **Solución basada en Contenedores Docker**: Equivale a introducir la mercancía dentro de un **contenedor marítimo estandarizado de acero**.
  - Sin importar si el transporte es un barco, un tren o un camión (servidor de desarrollo, pruebas o producción), el vehículo solo manipula un módulo estándar con dimensiones idénticas.
  - La mercancía interior opera en un entorno aislado con sus propias condiciones, garantizando un comportamiento idéntico en cualquier destino.

---

## Aplicación en el Proyecto QuestFest

En **QuestFest**, la infraestructura backend se define en el archivo `backend/docker-compose.yml`. Al ejecutar `docker-compose up`, Docker levanta el contenedor de la base de datos PostgreSQL (`questfest_postgres`) y el contenedor de la API FastAPI (`questfest_web`) conectados a través de una red privada virtual. Esto garantiza que la aplicación funcione de forma idéntica tanto en el ordenador del desarrollador como en el servidor final del evento.
