# 06.8 - ¿Qué es un ORM y cómo funciona SQLAlchemy?

## Explicación Técnica

Un **ORM** (*Object-Relational Mapper* o Mapeador Objeto-Relacional) es una técnica de programación que abstrae la capa de base de datos relacional permitiendo interactuar con tablas, filas y columnas mediante la sintaxis nativa de un lenguaje de programación orientado a objetos.

1. **Abstracción del Lenguaje SQL**: En lugar de escribir cadenas de texto SQL manuales (como `SELECT * FROM usuarios WHERE id = 1;`), el desarrollador manipula clases y objetos Python (ejemplo: `select(Usuario).where(Usuario.id == 1)`).
2. **SQLAlchemy 2.0 y Mapped Types**: SQLAlchemy es la biblioteca ORM líder en el ecosistema Python. En su versión 2.0 introduce anotaciones de tipo estáticas (`Mapped[str]`, `mapped_column`) que permiten la integración completa con linters y autocompletado en IDEs como VS Code.
3. **Gestión de Relaciones y Claves Foráneas**: Traduce automáticamente las relaciones complejas entre tablas (uno a muchos, muchos a muchos) en propiedades de objeto enlazadas mediante `relationship()`, gestionando la carga perezosa (*lazy loading*) o explícita (*selectinload*).

---

## Analogía del Intérprete Simultáneo

Para comprender la función de un ORM como SQLAlchemy, se puede analizar mediante la analogía de la comunicación con un traductor simultáneo:

- **La Base de Datos (PostgreSQL)**: Utiliza de forma exclusiva el lenguaje relacional **SQL**.
- **La Aplicación Backend (Python / FastAPI)**: Opera en el lenguaje orientado a objetos **Python**.
- **El ORM (SQLAlchemy)**: Actúa como el **intérprete simultáneo del sistema**.
  - Al requerir la creación de un nuevo participante con 100 QuestCoins en Python, el ORM traduce la orden al instante a una instrucción SQL estandarizada (`INSERT INTO usuarios ...`) y la transmite a la base de datos.
  - Al retornar PostgreSQL los resultados relacionales, el ORM los convierte de nuevo en objetos Python manipulables (`usuario.saldo_actual`) sin exigir la redacción manual de consultas SQL complejas.

---

## Aplicación en el Proyecto QuestFest

En **QuestFest**, todas las entidades del dominio —como las misiones, los tickets de apuesta de **QuestCoins**, los duelos 1vs1 y el historial de transacciones (`LedgerTransaccion`)— están definidas como clases Python en la carpeta `backend/app/models/`. SQLAlchemy se encarga de crear las tablas en PostgreSQL y mantener la consistencia de los datos.
