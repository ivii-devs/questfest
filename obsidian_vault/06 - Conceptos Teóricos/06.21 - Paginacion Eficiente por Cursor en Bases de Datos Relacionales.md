## Explicación Técnica

La división de grandes volúmenes de datos en conjuntos de registros navegables (*paginación*) es una técnica indispensable para optimizar el rendimiento y el tiempo de respuesta de las APIs web. En bases de datos relacionales como PostgreSQL existen dos enfoques principales:

1. **Paginación Basada en Desplazamiento (Offset-Based Pagination)**:
   - Sintaxis SQL: `SELECT * FROM publicaciones ORDER BY fecha_creacion DESC LIMIT 15 OFFSET 3000;`
   - **Problema de Rendimiento**: El motor de la base de datos debe leer e inspeccionar físicamente los 3.000 registros anteriores en el disco antes de descartarlos para devolver los 15 solicitados. La complejidad temporal escala de forma lineal $O(N)$ a medida que se avanza en las páginas.
   - **Problema de Inconsistencia (Desplazamiento de Datos)**: Si se inserta una nueva publicación mientras el usuario navega entre páginas, los registros se desplazan hacia abajo, provocando que el cliente reciba elementos duplicados o se salte registros.

2. **Paginación Basada en Cursor (Cursor-Based / Keyset Pagination)**:
   - Sintaxis SQL: `SELECT * FROM publicaciones WHERE id < 345 ORDER BY id DESC LIMIT 15;`
   - **Rendimiento Óptimo**: Utiliza un identificador único indexado (normalmente la clave primaria `id` o una marca de tiempo secuencial) como punto de referencia (*cursor*). El motor SQL realiza una búsqueda directa por índice B-Tree, saltando directamente a la ubicación exacta sin leer filas anteriores. La complejidad es constante $O(1)$.
   - **Estabilidad de Datos**: La inserción de nuevos registros en la parte superior de la tabla no altera la posición del cursor, garantizando que el usuario nunca vea publicaciones repetidas durante el desplazamiento (*scroll infinito*).

## Modelo Conceptual de Analogía: El Libro con Puntos de Libro frente a Contar Páginas

Considere un lector que está estudiando una enciclopedia médica de 5.000 páginas.

En el método de paginación por desplazamiento (OFFSET), cada vez que el lector desea consultar la lección número 200, debe abrir el libro en la página 1 y pasar manualmente las 199 páginas anteriores una por una contando con los dedos antes de comenzar a leer la página 200. Si alguien inserta un folio adicional en la portada mientras el lector cuenta, todo el conteo se desorganiza y el estudiante termina leyendo el capítulo equivocado.

En el método de paginación por cursor, el lector utiliza un marcapáginas codificado con el número exacto del folio anterior (ejemplo: *"continuar a partir del folio 345"*). Al volver al libro, abre la enciclopedia directamente en la lengüeta del marcapáginas 345 sin perder un solo segundo contando folios anteriores.

## Aplicación en el Proyecto QuestFest

En la plataforma QuestFest, la paginación por cursor garantiza que la experiencia de desplazamiento por el Muro Social y la tabla de clasificación sea sumamente fluida.

1. **Scroll Infinito en el Muro Social**: Al desplazarse hacia abajo en la pantalla principal (`page.tsx`), la aplicación cliente detecta que el usuario se aproxima al final de la lista mediante la API `IntersectionObserver` y solicita las siguientes 15 publicaciones pasando el parámetro `cursor_id` con el ID de la última publicación visible.
2. **Eficiencia en Servidor**: La consulta SQL en `publicaciones_crud.py` ejecuta una búsqueda indexada `WHERE id < cursor_id ORDER BY id DESC LIMIT 15`, manteniendo la respuesta del servidor en tiempos inferiores a 10 milisegundos independientemente de si el muro acumula 100 o 50.000 publicaciones durante el evento.
