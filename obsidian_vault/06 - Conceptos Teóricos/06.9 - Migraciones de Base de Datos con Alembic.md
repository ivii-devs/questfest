# 06.9 - Migraciones de Base de Datos con Alembic

> Enlace de navegación: Volver al [[06.0 - Indice y Mapa de Conceptos Teoricos]]

## Explicación Técnica

Las **migraciones de base de datos** son un sistema de control de versiones para la estructura (esquema) de una base de datos relacional. **Alembic** es la herramienta de migraciones oficial desarrollada para SQLAlchemy en Python.

1. **Evolución del Esquema sin Pérdida de Datos**: Durante el ciclo de vida del software, es habitual añadir campos a las tablas (ejemplo: añadir `avatar_url`), crear nuevas tablas o modificar restricciones. Rehacer la base de datos desde cero borraría todos los datos reales de los usuarios. Alembic aplica cambios alterando la estructura existente (`ALTER TABLE`) preservando los datos.
2. **Archivos de Revisión Incremental**: Cada cambio en el esquema se guarda como una "revisión" en un script de Python con dos funciones principales:
   - `upgrade()`: Contiene las instrucciones para aplicar los nuevos cambios en la base de datos.
   - `downgrade()`: Contiene las instrucciones inversas para revertir los cambios si ocurre algún error.
3. **Detección Automática (`autogenerate`)**: Alembic compara el estado actual de los modelos ORM en Python con el estado real de PostgreSQL y genera automáticamente el script de migración con las diferencias detectadas.

```mermaid

    Rev1["Revisión 001 (Init Schema)"] --> Rev2["Revisión 002 (Add QuestCoins Ledger)"]
    Rev2 --> Rev3["Revisión 003 (Add Cloudinary URL)"]
    Note over Rev3: Estado actual en producción (HEAD)
```

## Analogía del Historial de Reformas

Para comprender la función de Alembic, se puede analizar mediante la analogía de las reformas en un edificio:

- **Estructura Inicial**: Equivale a la construcción inicial de una instalación con sus estancias y accesos (tablas SQL).
- **Modificación de Requisitos**: Con el tiempo, surge la necesidad de incorporar un nuevo sector (añadir tablas de apuestas o campos de imagen).
- **Enfoque sin Alembic**: Equivale a demoler el edificio completo y reconstruirlo desde el origen. Esta acción destruiría los bienes y el equipamiento almacenados en su interior (pérdida de datos de usuarios y **QuestCoins**).
- **Enfoque con Alembic**: Equivale a disponer de un **cuaderno de planos de reforma incremental**. El arquitecto acude a las instalaciones existentes, ejecuta la ampliación exacta (`ALTER TABLE`) sin demoler las estructuras en servicio y registra en el cuaderno el plano detallado del cambio realizado.

---

## Aplicación en el Proyecto QuestFest

En **QuestFest**, las migraciones de Alembic se gestionan en la carpeta `backend/alembic/`. Al desplegar una nueva versión del sistema en Docker, la ejecución del comando `alembic upgrade head` aplica automáticamente las últimas modificaciones de esquema sobre la base de datos PostgreSQL sin borrar los saldos ni las misiones de los jugadores.
