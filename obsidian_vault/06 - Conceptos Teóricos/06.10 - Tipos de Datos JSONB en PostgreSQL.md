## Explicación Técnica

**JSONB** (JSON Binario) es un tipo de datos avanzado soportado por PostgreSQL que permite almacenar documentos JSON semiestructurados en formato binario descompuesto dentro de columnas relacionales.

1. **Flexibilidad frente al Esquema Rígido SQL**: A diferencia de las columnas relacionales tradicionales que requieren definir previamente el tipo y nombre exacto de cada columna, una columna `JSONB` permite guardar objetos anidados con número variable de propiedades (ejemplo: opciones de apuestas con cuotas dinámicas).
2. **Ventajas sobre el tipo JSON de Texto Plano**:
   - Se procesa y valida al insertarse en la base de datos.
   - Elimina espacios en blanco y claves duplicadas para optimizar almacenamiento.
   - **Indexación GIN (Generalized Inverted Index)**: Permite crear índices avanzados sobre las propiedades internas del documento JSON, permitiendo realizar búsquedas de alta velocidad sobre atributos específicos dentro del documento.
3. **Operadores Especiales de Consulta**: Permite consultar mediante operadores nativos de PostgreSQL como `->` (obtener campo), `->>` (obtener campo como texto) o `@>` (comprobar si contiene un subdocumento JSON).

## Analogía del Armario con Compartimentos Flexibles

Para comprender la utilidad del tipo JSONB, se puede analizar mediante la analogía de la organización en un módulo de almacenamiento:

- **Estructura Relacional Rígida (Tablas SQL)**: Equivale a un mueble compuesto por cajones de madera fija. Cada cajón cuenta con dimensiones predefinidas para un objeto concreto. La inclusión de un elemento con dimensiones o atributos variables exige modificar la carpintería del mueble (alteración de tablas).
- **Columna JSONB**: Equivale a una sección del mueble provista de **cajas organizadoras elásticas catalogadas mediante código de barras**.
  - Permite albergar objetos con múltiples combinaciones de opciones o atributos variables.
  - La catalogación binaria (_indexación GIN_) habilita la localización inmediata de un atributo interno (por ejemplo: _"Recuperar la Opción B del contrato de apuestas"_) sin requerir la inspección completa del mueble.

## Aplicación en el Proyecto QuestFest

En **QuestFest**, la tabla de apuestas (`apuestas`) almacena sus opciones en una columna `opciones` de tipo `JSONB` en el modelo `backend/app/models/juegos.py`. Esto permite que una apuesta sobre la fiesta tenga 2, 3 o 5 opciones distintas con cuotas multiplicadoras variables sin necesidad de crear una tabla relacional secundaria compleja.
