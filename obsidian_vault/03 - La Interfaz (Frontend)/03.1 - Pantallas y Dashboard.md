## Análisis Técnico: Arquitectura Next.js App Router

### 1. Cliente HTTP e Interceptores (`src/lib/axios.ts`)
Configurado para apuntar a la variable de entorno `NEXT_PUBLIC_API_URL` (por defecto `http://localhost:8000`). Incorpora un interceptor de peticiones (`api.interceptors.request.use`):
```typescript
if (typeof window !== 'undefined') {
  const token = localStorage.getItem('access_token');
  if (token) {
    config.headers.Authorization = 'Bearer ' + token;
  }
}
```
Este mecanismo garantiza que las peticiones emitidas por los componentes cliente adjunten la cabecera `Authorization: Bearer <token>` de forma centralizada sin requerir la inyección manual del token en cada llamada.

### 1.1. Sanitización de Errores y Compatibilidad con React 19 (`src/lib/errorHandler.ts`)
En React 19, cualquier intento de renderizar un objeto plano o un array de objetos como nodo hijo de la interfaz (`ReactChild`) desencadena una excepción crítica en tiempo de ejecución (`Objects are not valid as a React child`). Dado que FastAPI y Pydantic v2 devuelven los errores de validación HTTP 422 como un array de objetos (`[{ type, loc, msg, input }]`), el módulo `errorHandler.ts` expone la función `getApiErrorMessage(error, fallbackMessage)`. Esta función extrae de forma determinista y recursiva una cadena de texto plana legible, garantizando que los mensajes de notificación toast y los mensajes de alerta reciban siempre un tipo primitivo `string`.

### 2. Proveedor Global de Autenticación (`src/context/AuthContext.tsx`) y Grupo (`src/context/GroupContext.tsx`)
Envuelve la estructura completa de la aplicación en `layout.tsx` empleando la [[06.13 - Gestion del Estado Global y Context API|Context API de React]]:
- **`AuthContext`**: Gestiona la identidad del usuario a nivel global (`user`), estado de carga y métodos `login` y `logout`. Tras iniciar sesión, redirige al usuario hacia el Hub de Bienvenida (`/groups`).
- **`GroupContext`**: Administra la lista de comunidades a las que pertenece el jugador (`groups`), el grupo activo seleccionado (`activeGroup`), el saldo local de **QuestCoins** en dicho grupo y la función para cambiar de grupo o abandonarlo.

### 3. Navegación Móvil Adaptativa y Hub de Bienvenida (`BottomNav.tsx` y `src/app/groups/page.tsx`)
- **Hub de Bienvenida (`/groups`)**: Pantalla de entrada con 3 pestañas estructurada como App Shell:
  1. *Mis Grupos*: Tarjetas apiladas horizontales con menú de tres puntos, saldos independientes y modales de creación e ingreso con código de invitación.
  2. *Mi Perfil*: Gestión directa e interactiva de la identidad global de la cuenta. Proporciona edición in-place del nombre de usuario y biografía sin pantallas secundarias redundantes, así como la actualización directa de la foto de perfil integrada con Cloudinary (`/api/auth/me/avatar`), reflejándose instantáneamente en todas las comunidades del jugador.
  3. *Ajustes Generales*: Configuración centralizada de tema y paletas (`ThemeSettingsCard`), notificaciones push del dispositivo, estado PWA y cierre de sesión.
- **Flujo de Entrada y Prevención de Parpadeos (Anti-Flicker)**:
  El manifiesto de la PWA fija su punto de partida (`start_url`) en `/groups`. Adicionalmente, la ruta raíz (`src/app/page.tsx`) y el proxy perimetral de red (`src/proxy.ts`) actúan como pasarela pura de entrada (Root Gateway), respondiendo de forma instantánea con una redirección HTTP hacia el Hub de Bienvenida (`/groups`) para usuarios autenticados o hacia `/login` si no disponen de sesión. El Muro Social comunitario se desacopla formalmente hacia su propia ruta semántica: `/feed` (`src/app/feed/page.tsx`).
- **Barra de Navegación Flotante Liquid Glass (`BottomNav.tsx`)**: 
  Píldora flotante suspendida a ras del margen inferior de la pantalla mediante `fixed bottom-3 left-1/2 -translate-x-1/2 w-[94%] max-w-lg z-50 rounded-full`.
  - Condición de visibilidad estricta: La barra permanece oculta en rutas de administración, configuración global o autenticación (`/groups`, `/login`, `/register`, `/join`, `/offline`, `/settings`, `/perfil`), durante la inicialización de sesión (`authLoading || groupsLoading`) o cuando no existe un grupo activo seleccionado (`!activeGroup`). De este modo, se garantiza que la barra nunca parpadee ni se muestre indebidamente si el usuario no se encuentra dentro del contexto operativo de una comunidad activa.
  - Estética visual: Acabado traslúcido Liquid Glass de última generación con desenfoque de fondo profundo (`backdrop-blur-2xl bg-[#282a36]/70`), remate perimetral especular (`border border-white/15`), brillo de refracción superior e iluminación de profundidad (`shadow-[0_15px_35px_rgba(0,0,0,0.8),inset_0_1px_1.5px_rgba(255,255,255,0.22)]`).
  - Posicionamiento ergonómico: Al ubicarse a escasos 12px del margen físico inferior con relleno simétrico y compacto (`py-1.5`), reposa de forma natural y limpia sobre la base de la pantalla sin franjas ni márgenes inferiores sobrantes, emulando la barra flotante de Safari en iOS.
  - Dinámica adaptativa:
    - Para miembros estándar (6 pestañas): `/feed` (Feed), `/ranking` (Ranking), `/bets` (Apuestas), `/missions` (Misiones), `/duels` (Duelos) y `/stats` (Estadísticas y libro mayor local).
    - Para administradores de grupo (7 pestañas): Añade la pestaña **Admin** (`/admin`), otorgando acceso instantáneo a la gestión de la comunidad y resolución de disputas.
  - Indicador de estado y microinteracción: La pestaña activa se resalta mediante una microcápsula con sombra luminosa de acento (`bg-dracula-purple/20 shadow-[0_0_12px_rgba(189,147,249,0.4)]`) y cada pestaña presenta microescalado elástico a la pulsación táctil (`active:scale-90`).

### 4. Arquitectura de Pantalla App Shell Homogénea
Todas las pantallas del sistema (`/feed`, `/ranking`, `/bets`, `/missions`, `/duels`, `/stats`, `/admin`, `/user/[username]`, `/perfil/stats/[type]`) adoptan el patrón `app-shell-page`, mientras que rutas históricas como `/settings` y `/settings/editar` actúan como redirecciones canónicas inmediatas hacia `/groups?tab=ajustes` y `/groups?tab=perfil` respectivamente:
- Contenedor raíz: `div.app-shell-page` rígido e inamovible (`fixed inset-0 w-full h-[100dvh] overflow-hidden select-none`).
- Cabecera: `header.flex-shrink-0` con desenfoque de fondo `backdrop-blur-md`, elevación adaptativa `.app-shell-header` (con sombra sutil en modo claro y desenfoque suave en oscuro) y relleno superior `pt-safe-top` para salvaguardar el notch y Dynamic Island de iPhone. El encabezado del muro social se titula de forma limpia como "Feed".
- Contenedor de contenido: `main.app-shell-scroll pb-28` con inercia táctil y scroll confinado de forma estricta para evitar colisiones con las barras del sistema operativo.
- Desplazamiento elástico táctil (`PullToRefresh`): Se aloja en el interior de `app-shell-page`, envolviendo exclusivamente el elemento desplazable `main` y preservando el `header` inmóvil en la parte superior para evitar desbordamientos visuales o bandas oscuras.

## Modelo Conceptual de Analogía: Aplicación Móvil del Recinto

Para comprender la estructura de la interfaz, puede analizarse mediante la analogía de la guía digital del evento:

1. **El Mostrador de Recepción o Hub de Bienvenida (`/groups`)**:
   Es el hall de entrada general. Aquí el visitante puede revisar su acreditación personal (Mi Perfil), configurar las preferencias generales y consultar a qué carpas o peñas tiene acceso, permitiéndole entrar a la que desee o canjear una invitación para una nueva peña.

2. **El Espacio Interior de la Carpa (`/`) y la Pantalla de Estadísticas (`/stats`)**:
   Al cruzar el umbral de una carpa, la aplicación se sumerge en las dinámicas locales de esa comunidad. La pantalla de Estadísticas actúa como el cuaderno de contabilidad personal de esa peña, reflejando el saldo de QuestCoins acumulado en ella y la posición en el ranking interno.

3. **La Barra Inferior de Navegación (`BottomNav`)**:
   Funciona como la botonera de acceso rápido situada al alcance del pulgar. Para los administradores de la carpa, despliega automáticamente el botón de mando para abrir el panel de control del grupo sin tener que rebuscar en menús secundarios.

## Decisiones de Arquitectura de Software

- **Inyección de Tokens mediante Interceptor de Axios**: Centralizar la adición del encabezado de autenticación previene omisiones accidentales en peticiones secundarias y simplifica el mantenimiento del código cliente.
- **Desacoplamiento entre Hub Global y Espacio de Grupo**: Separar el perfil global en el Hub y mover las estadísticas y el historial contable a una ruta interna (`/stats`) garantiza que las dinámicas de juego permanezcan estrictamente contextualizadas.
- **Navegación Adaptativa según Rol en Grupo**: La adición dinámica de la pestaña de administración en la barra inferior para los administradores de grupo optimiza la accesibilidad y velocidad de respuesta ante eventos en vivo.
- **Estandarización del Patrón App Shell**: Unificar la estructura de cabecera fija y cuerpo con scroll aislado en todas las vistas elimina cualquier disparidad visual entre pantallas, asegurando que la experiencia en iPhone sea idéntica a una aplicación nativa.
